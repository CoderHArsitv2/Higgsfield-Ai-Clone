Fixed, and I reproduced the exact production error locally first.

## Root cause

The Vercel project's **Framework Preset was "Other"**, not Next.js. I confirmed this from the project itself:

```
Root Directory      frontend
Framework Preset    Other
```

With no Next.js preset, Vercel never invoked `@vercel/next`. Instead it saw a root-level `middleware.ts` and built it with `@vercel/node` as a standalone function, emitting ESM `import` into `middleware.js` whose nearest package.json ([frontend/package.json](frontend/package.json)) has no `"type": "module"` — exactly your `SyntaxError: Cannot use import statement outside a module`.

I reproduced it by building without the fix — builders came out as `['@vercel/node', '@vercel/static-build']` with only `middleware.func` produced, plus Vercel's tell-tale *"middleware.ts uses the deprecated edge runtime"* warning from its standalone middleware builder. Note this meant the whole app was broken, not just middleware: no app-router routes were being deployed at all.

## Second, independent bug

While verifying, I found the deploy workflow also broken. [deploy-prod.yml](.github/workflows/deploy-prod.yml) ran the Vercel CLI with `working-directory: frontend`, but the CLI resolves the project's Root Directory (`frontend`) *relative to the cwd* — so it looked for `frontend/frontend`, found nothing, and produced output with zero functions and a bare 404 route. That deploy publishes an empty site.

## Changes

- **[frontend/vercel.json](frontend/vercel.json)** (new) — pins `"framework": "nextjs"`, overriding the dashboard preset and keeping it in version control.
- **[deploy-prod.yml](.github/workflows/deploy-prod.yml)** — dropped `working-directory: frontend` from the Vercel job so the CLI runs from the repo root.
- **[.gitignore](.gitignore)** — ignore the root `.vercel/` the CLI now writes there.

## Verification

Building from the repo root with the fix now gives `builders: ['@vercel/next']`, all 8 routes as functions, and middleware as a proper edge function (`"runtime": "edge"`, `"framework": {"slug": "nextjs"}`). `prettier --check`, `tsc --noEmit` and `eslint` all pass; both workflow files parse.

Two things I deliberately did not do: I left the dashboard's Framework Preset as "Other" (`vercel.json` overrides it, and changing your live project settings felt like your call — say the word and I'll flip it too), and I haven't committed anything.
